# HYDRAGROW Agent Goals

## Outcome

Enable reliable, auditable agent-driven engineering for the frontend overhaul without changing HYDRAGROW's domain authority, safety boundaries, or delivery governance.

## Success conditions

- Agent instructions point to authoritative repository sources instead of duplicating them.
- Each implementation phase has explicit scope, non-goals, acceptance criteria, verification, and an approval gate.
- Material discoveries and decisions survive across sessions.
- Verification evidence is recorded as observed evidence, not inferred from intent.
- Planning/harness work cannot silently authorize application implementation.
- Existing HYDRAGROW skills remain the reusable execution layer; the harness does not duplicate them.

## Non-goals

- No new agent runtime or model dependency.
- No multi-agent swarm, voting, or retry framework unless later evidence shows a concrete need.
- No application-code changes as part of harness setup.
- No replacement of `.agent/verify.yml` or `docs/DELIVERY-GOVERNANCE.md`.
